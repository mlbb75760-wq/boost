# Что изменено

## Обязательно сделать перед запуском
1. В переменных окружения теперь **обязательны** `BOT_TOKEN`, `DATABASE_URL`, `CLICK_CARD`, `PAYNET_CARD`
   (без них бот не стартует с понятным сообщением — раньше показывал клиентам карту 0000 0000 0000 0000).
2. Рекомендуется задать `ADMIN_USER_IDS` (user_id админов через запятую) — иначе админом считается
   любой участник `ADMIN_CHAT_ID`. Остальные переменные — в `.env.example`.
3. Схема БД обновится сама при старте (новая колонка `balance_logs.kind`, индексы, UTC-значения по умолчанию).

## Критичные
- Бесплатный лимит проверяется атомарно при подтверждении заказа (нельзя обойти старой кнопкой).
- Списание денег + создание заказа — одна транзакция; админ уведомляется до действий с сообщением пользователя;
  если канал заявок недоступен — заявка дублируется в ADMIN_CHAT_ID. Баланс не уходит в минус.
- Отмена заказа из канала заявок работает (отдельная обработка channel_post).
- Отмена + возврат — одна транзакция; финальные статусы нельзя перезаписать устаревшей кнопкой.
- Нет нулевых реквизитов по умолчанию; проверка обязательных переменных.

## Средние
- Весь пользовательский текст экранируется (html.escape); ссылки валидируются строго с якорем `$`.
- Ссылки из приложений (`?igsh=`, `?_t=`, `?si=`), Shorts, `m.youtube.com`, `vt.tiktok.com` принимаются.
- Нечисловой ввод/фото/«²» больше не роняют обработчики.
- Статистика: пополнения, возвраты и ручные правки считаются раздельно (`kind`).
- Время для пользователей — местное (`TZ_OFFSET_HOURS`, по умолчанию +5); в БД всё в UTC.
- Рассылка: защита от двойного запуска, паузы, повтор при флуд-лимите.
- Бан: проверка в «Помощи» и пополнении, лимит чеков и антиспам поддержки; разбан полностью сбрасывает счётчики.
- `confirm_order` работает только в состоянии подтверждения; устаревшие кнопки получают ответ.
- `/topup` не создаёт «призраков» (UserNotFound), не уводит баланс в минус.

## Мелкие
- `/start` сбрасывает состояние; «Назад» из бесплатного варианта ведёт в бесплатный раздел.
- После смены статуса заказа сохраняется кнопка «Назад» и обновляется строка «Статус».
- Глобальный обработчик ошибок и защита от устаревших сообщений; callback всегда получает ответ.
- Состояния диалогов хранятся в Postgres (таблица `fsm_states`) и переживают перезапуск/редеплой; Redis не нужен
  (но если задать `REDIS_URL`, будет использован он). Ожидание причины отмены из канала тоже хранится в БД.
- Накопленные за простой сообщения больше не сбрасываются (чеки не теряются).
- Проверка версии Python при старте (нужен 3.10+), файл `.python-version` (3.12) для хостинга.
- Предупреждение в логах, если `ADMIN_CHAT_ID` — группа, а `ADMIN_USER_IDS` не задан.
- Индексы, очистка `invalid_events`, удалены `handlers/123.py` и лишний импорт.

## Включено по вашей просьбе
- Бесплатные подписчики Telegram (10–30 раз в 7 дней) теперь доступны в разделе «Бесплатное продвижение».
  Чтобы отключить — удалите `"subs": "tg_subs"` из `FREE_PROMO_SERVICES` в `keyboards.py`.

## Проверка времени в старых записях
Если база раньше работала не в UTC, у СТАРЫХ записей время могло быть записано в другом поясе.
Проверить: `SHOW timezone;` в Postgres. Если вернулось `UTC` — всё в порядке. Новые записи пишутся в UTC всегда.
